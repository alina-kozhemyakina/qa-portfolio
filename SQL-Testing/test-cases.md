# SQL Data Checks — Test Cases

Набор учебных проверок для таблиц `customers` и `orders`.

## Тестовые сценарии

| ID | Проверка | SQL-условие / подход | Ожидаемый результат на тестовых данных |
|---|---|---|---|
| SQL-001 | Получение списка покупателей | `SELECT name, city FROM customers` | 5 покупателей |
| SQL-002 | Фильтрация заказов по сумме | `WHERE amount > 1000` | Заказы 101, 103, 104, 105 |
| SQL-003 | Фильтрация по двум условиям | `status = 'completed' AND amount > 1000` | Заказы 101, 103, 105 |
| SQL-004 | Уникальные статусы | `SELECT DISTINCT status` | `completed`, `pending`, `cancelled` |
| SQL-005 | Подсчёт заказов по покупателям | `LEFT JOIN` + `COUNT(orders.id)` | Анна — 2; Иван — 1; Мария — 1; Петр — 1; Елена — 0 |
| SQL-006 | Сумма заказов по покупателям | `LEFT JOIN` + `SUM` + `COALESCE` | Анна — 4000; Иван — 800; Мария — 1200; Петр — 3000; Елена — 0 |
| SQL-007 | Покупатели без заказов | `LEFT JOIN` + `WHERE orders.id IS NULL` | Елена |
| SQL-008 | Покупатели с завершёнными заказами | `EXISTS` | Анна, Петр |
| SQL-009 | Покупатели без завершённых заказов | `NOT EXISTS` | Иван, Мария, Елена |
| SQL-010 | Покупатели с 2+ заказами на сумму более 2000 | `GROUP BY` + `HAVING` | Анна: 2 заказа, сумма 4000 |
| SQL-011 | Покупатели, у которых все заказы отменены | `GROUP BY` + условный `SUM(CASE...)` + `HAVING` | Мария |
| SQL-012 | Заказы с некорректной суммой | `WHERE amount <= 0` | Нет записей |
| SQL-013 | Заказы без существующего покупателя | `LEFT JOIN` + `WHERE customers.id IS NULL` | Нет записей |
| SQL-014 | Покупатели без города | `WHERE city IS NULL` | Нет записей |

## Примечания для QA

- `COUNT(orders.id)` считает только реальные найденные заказы после `LEFT JOIN`. `COUNT(*)` в такой ситуации может посчитать строку покупателя даже при отсутствии заказа.
- `WHERE` фильтрует строки до группировки, а `HAVING` — группы после `GROUP BY`.
- `IS NULL` используется для проверки `NULL`; сравнение вида `= NULL` некорректно.
- `NOT EXISTS` в SQL-009 возвращает также покупателей, у которых вообще нет заказов.
- Проверки SQL-012 и SQL-013 демонстрируют полезные QA-запросы. В этой учебной схеме ограничения `CHECK` и `FOREIGN KEY` предотвращают часть таких некорректных данных на уровне базы.

## Результат

Запросы проверены логически на тестовом наборе из 5 покупателей и 5 заказов. Перед использованием в другом SQL-движке может потребоваться адаптация синтаксиса.
